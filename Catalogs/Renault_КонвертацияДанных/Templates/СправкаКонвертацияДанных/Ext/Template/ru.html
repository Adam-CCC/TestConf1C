Идентификация объектов по умолчанию осуществляется по уникальному идентификатору ссылки УникальныйИдентификатор.
Так же возможен вариант программного поиска, при этом используюется ПравилоПоиска.
После инициализации и загрузки объекта но до его записи возможна программная обработка, при этом используется Правило.

Резальтатом вычисления правил типа Программа должна быть переменная "Значение"

Правила могут распространяться на объекты, реквизиты и табличные части.

1. ПРАВИЛА РЕКВИЗИТОВ

Правила могут быть переопределены.
Если у реквизита установлено правило то оно будет замещать правило загружаемой ссылки.

Например в справочнике "Контрагенты" реквизит "ФизЛицо" имеет тип "Справочники.ФизическиеЛица".
Имеем 2 правила:
1. Справочник.ФизическиеЛица - правило ссылки
2. Справочник.Контрагенты.ФизЛицо - правило реквизита 
Приоритет правила реквизита, если его нет то действует основное правило для ссылок этого типа

Аналогично работает свойство "ТолькоЧтение".
Его назначение - блокировать запись объекта.
Например возможна загрузка объекта + программная обработка посредствам Правил но без дальнейшей записи самого объекта.

2. ПРАВИЛА ТАБЛИЧНЫХ ЧАСТЕЙ

Табличные части могут быть реальными и виртуальными.
Виртуальные они могут быть и на стороне Источника и на стороне Приемника.
Например для справочника Контрагенты дополнительно выгружается регистр сведений КонтактнаяИнформация в составе
элемента справочник Контрагенты как его табличная часть.

На стороне Источника это выглядит как ОбъектыМД где имя=Справочник.Контрагенты.Контакты.
"Контакты" - произвольное имя, при том что физически не существует такой табличной части.
Настройка такого объекта описана в справке ОбъектыМД.

На стороне Приемника создается элемент справочника "Конвертация данных" где внешние метаданные (реальные или виртуальные)
выбираются из списка существующих, а собственные метаданные указывают на физическую таблицу 
(в нашем случае РегистрСведений.КонтактнаяИнформация).

Гарантированна запись регистра только при наличие всех полей измерений.
При этом если не указаны правила поиска для таблицы (РегистрСведений.КонтактнаяИнформация) то запись регистра выполняется
построчно. Это снижает производительность при большом объеме данных.
Предпочтителено указать Правла поиска в таблице (РегистрСведений.КонтактнаяИнформация) при этом будет выполнятся пакетная
запись регистра НаборЗаписей, что положительно влияет на производительность.

Правила поиска в таком контексте должны выполнять отбор по регистру, пример:
НаборЗаписей=РегистрСведений.КонтактнаяИнформация.СоздатьНаборЗаписей();
...
//правила поиска типа Программа
НаборЗаписей.Отбор.Объект.Установить(КонтрагентСсылка)
//конец правил поиска типа Программа
...
ЗаполнитьЗначенияСвойств(НаборЗаписей.Добавить(),Строка)

Для вычисления переменных необходимых для правила используется переменная "ДанныеВнСсылки" из контекста процедуры

Правило - формула, программа, значение, ссылка ...
